## 설계 — 누가 판단하는가

|           | 안 A — MPU가 다 판단     | **안 B — MCU가 최종 판단** ✅ |
| --------- | ------------------- | ---------------------- |
| MCU 역할    | 시키는 대로 모터만          | 거리 판단 + 최종 정지 결정       |
| MPU 역할    | 거리도 받고 영상도 보고 전부 결정 | **"병 보임/안 보임"만 알려줌**   |
| Wi-Fi 끊기면 | 로버가 안 멈춤 ❌          | 거리센서로는 계속 멈춤 ✅         |
| 리눅스가 버벅이면 | 반응 지연 ❌             | 정지 반응은 그대로 ✅           |

```
MCU  : 거리 읽기 (20 Hz) → 자기가 판단 → 즉시 정지          [빠르고 확실]
MPU  : 영상 추론 (수 Hz) → bottle 있나? → true/false만 전달  [느리고 똑똑]
MCU  : (거리로 막힘) OR (영상으로 막힘) → 정지               [최종 결정]
```

> 🔑 **안전에 관한 판단은 가장 단순하고 가장 확실한 쪽에 둡니다.**
> 실제 자율주행 시스템도 같은 구조입니다. 인지·계획은 상위 컴퓨터가, 비상 제동은 하위 MCU가.

## 흔한 실패

| 증상 | 원인 | 확인 |
|---|---|---|
| 아예 안 움직임 | TODO① 에서 `-1`을 "가깝다"로 처리 | 시리얼 모니터에 `distance_mm=-1`이 계속 뜨는지 |
| 병 치워도 안 움직임 | `HOLD_SEC`가 너무 김 / TODO④ 안 채움 | 로그의 `vision_blocked=`가 False로 바뀌는지 |
| 병 들었는데 안 멈춤 | 라벨 오타 (`"Bottle"` ✗) / confidence 임계값이 높음 | 웹 화면 검출 목록에 `bottle`이 뜨는지 |
| 덜덜거리며 전진 | `HOLD_SEC`가 너무 짧음 | 검출이 끊기는지 |
| 로버가 버벅임 | 매 루프마다 `brake()` 호출 | `wasMoving` 로직 확인 |
| Python은 도는데 MCU가 반응 없음 | `Bridge.provide` 이름 오타 | 양쪽 문자열이 **똑같은지** |
| 영상만 안 뜸 | 컨테이너가 아직 안 뜸 | `docker ps` · 1초마다 재시도 중이니 기다려 보기 |
